# Hammer++ scale compatibility

Статус: начальное эмпирическое исследование, матрица не завершена.

Дата снимка: 2026-08-20.

## Источник наблюдений

- Карта: `psr_scale_compatibility_01a.vmf`.
- Внешний read-only источник: `antenna_sdk2013/maps/psr_scale_compatibility_01a.vmf`.
- SHA-256 снимка: `b6a5a5827ec4bf8cbeeed8163ac1b85d9d17560a2759d2062b4342c928afd6ed`.
- Размер: 41 255 байт.
- Структурная проверка: VMF валиден.
- Активные `prop_static_scalable`: 29.
- Скрытые top-level блоки: 0.
- Тестовая модель во всех запросах: `models/apt/fsmit01.mdl`.

Во всех 29 сущностях поле `debug_string` имеет машинно-читаемый формат `effective_scale=<value>` и служит test oracle ожидаемого результата PSR для raw `modelscale`. Обычно oracle совпадает с визуальным масштабом Hammer++, но уже включает единственное продуктовое исключение: raw `0.001` визуально выглядит как `0.001`, а oracle равен `0.01` из-за нижнего clamp PSR. Поле не является частью production/cache schema.

Для анализа исключения различаются три значения. Название `effective_scale` в `debug_string` относится к test oracle ожидаемого результата PSR и не означает поле production-модели:

| Raw `modelscale` | Hammer-compatible effective scale | PSR compile scale |
|---|---:|---:|
| `0.001` | `0.001` | `0.01` |
| `1.01` | `1.01` | `1.01` |
| `1.02` | `1.02` | `1.02` |
| `1.5` | `1.5` | `1.5` |
| `0.5` | `0.5` | `0.5` |

Clamp `effective < 0.01 -> compile 0.01` — единственное утверждённое исключение из общего правила следования визуальному поведению Hammer++. Оно вводится намеренно: модели меньшего масштаба практически бесполезны и вредны для производительности. В production/cache PSR сохраняет raw и compile scale и выдаёт понятную диагностику; effective scale остаётся только тестовым oracle и не сериализуется.

## Первичная гипотеза

Поведение строк с запятой совместимо с гипотезой, что Hammer++ читает допустимый числовой префикс до запятой, а затем применяет fallback для нулевого или непригодного результата:

- `2,0 -> 2.0`;
- `1,5 -> 1.0`;
- `0,5 -> 1.0`;
- `0,01 -> 1.0`.

Это только гипотеза. Она не должна становиться реализацией до проверки значениями `2,5`, `3,9`, `10,5`, `0,99`, отрицательными значениями и строками с числовым префиксом/суффиксом.

## Что ещё нужно проверить

### Парсинг

- отсутствующий `modelscale` и пустая строка;
- leading/trailing whitespace, если Hammer сохраняет его в VMF;
- `0`, `0.0`, `-0`, отрицательные значения и явный `+`;
- `1.`, `.5`, ведущие нули и несколько точек;
- exponent notation;
- числовой префикс с текстовым суффиксом и текстовый префикс с числом;
- дополнительные значения с запятой;
- `nan`, `inf` и аналоги, если Hammer позволяет сохранить их.

### Пределы

- значения непосредственно ниже, на уровне и выше `0.01`;
- дополнительные значения ниже `0.01`, подтверждающие единый нижний clamp;
- верхняя поддерживаемая граница выше `55`;
- поведение при overflow и очень длинных числах.

### Округление и имя артефакта

- различает ли viewport `1.001`, `1.004`, `1.005`, `1.009`, `1.01` и `1.02`;
- сколько значащих знаков сохраняет Hammer++;
- как PSR compile scale преобразуется в канонический целый процент `_scaled_XXX`;
- что делать, если визуально различные масштабы схлопываются в один целый процент.

## Рекомендуемый формат следующих отметок

Все текущие сущности уже используют основной машинно-проверяемый формат:

```text
effective_scale=1.0
effective_scale=0.01
```

Для ещё не измеренных будущих случаев можно временно использовать:

```text
unsupported=<краткое описание наблюдаемого поведения>
needs_measurement=<что именно сравнить>
```

При переносе карты в автоматические fixtures допустимы только окончательные записи `effective_scale=<value>`; временные отметки должны приводить к пропуску или явному отказу теста, а не превращаться в ожидаемое число.

## Условие завершения исследования

Этап считается завершённым, когда для каждой строки известны raw value и test oracle `effective_scale`, отдельно документированы намеренные расхождения с viewport, а также утверждены пределы, округление и детерминированный алгоритм имени `_scaled_XXX`.
