# Правила работы с props_scaling_recompiler

## Обязательные repo skills

- Для любого изменения рабочего кода, тестов, поведения, зависимостей или сборочной конфигурации использовать `$psr-dev-cycle`. Он задаёт выбор regression-тестов, проверку результата и обязательный release/install цикл.
- Для проектирования, изменения, диагностики или ревью scale/skin, VMF/KeyValues, GameInfo/SearchPaths, MDL/QC, VMT/materials, cache/cleanup либо стадий pipeline дополнительно использовать `$psr-pipeline-contracts` и читать только перечисленные там релевантные references.
- Перед архитектурными изменениями, изменением форматов данных, VMF/QC/VMT-пайплайна или правил генерации ассетов прочитать `docs/PROJECT_CONTEXT.md` целиком.

## Постоянные границы проекта

- Целевая платформа первого релиза 2.0 — только Source SDK 2013 Singleplayer под Windows.
- `props_scaling_recompiler_v1.1.2.py` — поведенческий референс последнего релиза, но не образец архитектуры.
- `props_scaling_recompiler.py` — незавершённый прототип 2.0. Не считать его production entry point и не достраивать отдельные заглушки без проверки целого pipeline. Рабочая реализация находится в пакете `psr`, entry point — `psr_entrypoint.py`/`psr.cli`.
- Сохранять существующие пользовательские изменения и не исправлять несвязанный dirty worktree. В частности, пользовательскими считаются текущие локальные изменения версии и все изменения, существовавшие до начала задачи.

## Внешнее окружение и разрешения

- Реальный проект Antenna и установленный SDK являются внешним тестовым окружением. Не изменять их файлы без явного запроса пользователя на конкретный запуск или тест.
- Постоянное исключение: после каждого полезного проверенного изменения рабочего кода, поведения, зависимостей или сборочной конфигурации пользователь разрешил заменить только `C:\Program Files (x86)\Steam\steamapps\common\Source SDK Base 2013 Singleplayer\bin\props_scaling_recompiler.exe` свежесобранным EXE. Другие файлы SDK или Antenna это разрешение не охватывает.
- Не запускать force-cleanup, массовую рекомпиляцию Antenna, Hammer или игру без явного запроса на конкретную внешнюю проверку. Для разрешённого запуска сначала прочитать external-validation reference из `$psr-dev-cycle`; snapshot пользовательских registry/CFG/video-настроек, восстановление в `finally` и доказательство восстановления обязательны.

## Неизменяемость и владение ассетами

- Никогда не изменять оригинальные MDL, QC, VMT и другие исходные ассеты.
- Все generated models PSR 2.0 размещать только под `models/psr_scaled/`, а generated materials — только под `materials/models/psr_scaled/`, сохраняя внутреннюю структуру исходного логического пути.
- Не принимать `models/psr_scaled/**` за оригинальный ассет; завершать такой request диагностикой, а не рекурсивной генерацией.
- Managed-пространства можно актуализировать только на основании валидного manifest/cache и завершённого плана. Legacy `_scaled_XXX` и `_static` вне `psr_scaled` не удалять обычным cleanup.

## Транзакционная безопасность

- Сохранять pipeline `discover -> plan -> generate -> validate -> commit`. VMF и постоянный cache/manifest обновлять только после проверки всех необходимых выходных артефактов.
- Никогда не записывать в VMF ссылку на модель, компиляция которой не подтверждена, и не удалять старый артефакт до разрешения и подготовки его оригинального источника.
- Считать VMF, GameInfo и VMT структурным Valve KeyValues. Не редактировать VMF регулярными выражениями через блоки или фигурные скобки; сохранять незатронутые байты настолько, насколько возможно.

## Проверка и поставка

- Для изменения поведения сначала добавлять небольшой fixture/regression test, затем менять реализацию. После изменения проверять синтаксис, целевые тесты, структурную валидность выходов и итоговый diff.
- После полезного изменения рабочего кода, поведения, зависимостей или сборочной конфигурации, прошедшего проверки, обязательно выполнить release-сборку, frozen regression, установку разрешённого EXE и сверку SHA-256 по `$psr-dev-cycle`.
- Изменения только документации, AGENTS или skills не требуют пересборки и установки EXE.
